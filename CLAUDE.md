# Vision Pipeline

Small visionOS app (SwiftUI + RealityKit) used to prove out CI/CD and prototype
3D visualisation for a future Kubernetes app. Repo: github.com/danielelisi/vision-pipeline

## Workflow rules

- **Always push.** After making changes, commit and push to `main` without asking.
  Don't wait for confirmation, even for tags.
- **Ship by tagging.** When a change is meant to be tried on device, push a
  semver tag (`vX.Y.Z`) to trigger the TestFlight job. Don't ask first. Bump the
  minor version for features and the patch version for fixes. Never move or reuse an
  existing tag.
- **Versions must be above 1.0.0.** TestFlight already has a 1.0 (1) build from
  before versioning was fixed, so 0.x tags conflict. The next tag is always higher
  than the latest `v1.*` tag (`git tag --sort=-v:refname | head -1`).
- **CI is the compiler.** Development happens on Linux, so code can't be built
  locally. After pushing, watch the run (`gh run watch <id> --exit-status`) and
  fix any failures before calling the work done.

## Project notes

- The Xcode project is generated by XcodeGen from `project.yml`. Don't commit
  `*.xcodeproj` or `Info.plist`; put Info.plist keys under `info.properties` in `project.yml`.
- The marketing version comes from the tag (`v1.2.0` → `1.2.0`). The build
  number is the GitHub run number.
- Signing is cloud-managed through an App Store Connect API key (repo secrets
  `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8_BASE64`, `APPLE_TEAM_ID`). No local
  certificates are needed.
- Bundle ID: `dev.daniele.visionpipeline`. visionOS requires the layered
  `AppIcon.solidimagestack` for TestFlight validation.
- `ITSAppUsesNonExemptEncryption: false` is set so builds skip the export
  compliance question. If real encryption is ever added (anything beyond HTTPS/OS
  crypto), revisit this.
- Test cluster code is in `VisionPipeline/Network/`. `ClusterTopology.swift` holds
  the data; the scene builder and the animation System never hard-code topology.
